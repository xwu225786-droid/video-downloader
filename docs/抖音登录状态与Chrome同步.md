# 抖音登录状态与 Chrome 同步

设置中提供两种方式：

1. **从 Chrome 同步**：读取 Chrome 最近使用的用户资料中抖音相关 Cookie。只查询 douyin.com、iesdouyin.com 及子域，不导出整个 Cookie 数据库，不读取或解密其他网站的 Cookie。macOS 可能要求钥匙串授权；授权及首次扫码、验证码仍需本人完成。未检测到可用会话时保留原有应用登录信息。
2. **登录 / 刷新登录信息**：先在后台复用应用专用用户资料；可保存时不显示窗口。需要交互时才打开浏览器，页面每秒检查一次，检测到会话且未处于登录或可识别的验证页面后自动保存并关闭窗口。保留“手动检查并保存”作为备用。

“已保存”表示本机保存了未到期的登录会话信息，不承诺平台一定接受下一次下载。匿名 Cookie 不再被视为登录凭据。认证文件原子写入，权限为 0600；接口只返回状态，不返回 Cookie 内容。

队列中旧任务的 Cookie 错误不再修改设置中的当前登录状态。旧后台遗留的“Cookie 已失效”错误在卡片上改为提示检查登录或完成验证，不直接声称到期。

下载错误源码区分：

- 明确要求登录或会话到期：更新登录状态。
- 验证码或安全验证：完成平台验证。
- HTTP 403 / 429：访问被拒绝或请求受限。
- 下载器要求 fresh cookies：检查登录信息，不据此认定过期。
- 超时及 SSL 校验失败：不归类为 Cookie 失效。

当前主后台保持运行，使用辅助端口 18766 的新版认证流程；新后台启动后直接使用正式认证接口。下载器的细分错误分类已改源码，当前驻留主后台仍使用旧版分类函数，下次正常启动时加载。当前界面的误报修复和新认证流程已经可用，无需为此次更新重启主后台。

Chrome 同步目前针对 macOS 的 Chrome v10 Cookie 解密路径，依赖系统访问权限和 yt-dlp 解密实现；其他加密格式不会当作明文导入。Cookie 同步不等于复制浏览器的全部会话环境，也不保证绕过平台访问限制。

验证：86 项相关测试通过，覆盖错误分类、匿名/过期凭据拒绝、后台复用、登录窗口自动保存、验证页面不自动关闭、仅解密抖音域名、导入失败保留原文件、外部来源拒绝。隔离界面验证覆盖旧错误覆盖问题、自动保存、辅助接口兼容及同步失败反馈。真实 Chrome Cookie 未读取，钥匙串未调用；只有用户点击同步后才会执行。主进程 PID 35296 未变，已核对 8 条近期终态任务和 162 个素材文件未改变。
